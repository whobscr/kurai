## Части {#parts}

| Часть | Контейнер | Что делает |
|---|---|---|
| **web** | `kurai-web` | Веб-приложение (FastAPI): страницы, вход и двухфакторный вход, веб-плеер (музыку и обложки берёт у Navidrome от имени пользователя), «Спросить», «Кабинет», «Системные настройки», справка. Показывает админку Navidrome и приложений плагинов на вкладке «Приложения» — только администраторам и через свой вход. Тяжёлую работу сам не делает: кладёт задачу в очередь. |
| **worker** | `kurai-worker` | Фоновые задачи из очереди: синхронизация библиотеки и прослушиваний, векторы, анализ звука, вкусы, ночные миксы, «Моя волна», «Спросить», задачи плагинов. Здесь же работают Telegram-бот и отправка уведомлений. Две полосы: срочная (то, чего ждёт человек) и ночная. |
| **Navidrome** | `kurai-navidrome` | Музыкальный сервер: читает папку с музыкой, отдаёт её плеерам по протоколу Subsonic, записывает прослушивания, звёзды и оценки. Пользователи заводятся в Kurai и переносятся сюда сами. |
| **PostgreSQL** | `kurai-postgres` (профиль `db`) или своя база | Всё состояние Kurai: настройки (секреты — зашифрованы), пользователи, очередь задач, треки и их векторы (pgvector), прослушивания, вкусы, плейлисты, уведомления. Музыки и паролей Navidrome здесь нет. |
| **Модели** | `kurai-llama`, `kurai-llama-embed` (профили `cpu`/`gpu`) или облако | Модель для текста превращает просьбу в план подборки, придумывает названия и объяснения. Модель эмбеддингов превращает описание трека (теги, жанры, исполнитель) в вектор. Без модели для текста всё работает, кроме названий, объяснений и «Спросить». |
| **audio** | `kurai-audio` (профиль `audio`) | По желанию: слушает сами файлы (Essentia — темп, настроение, жанр; CLAP — поиск по описанию звучания). Его зовёт только worker. |
| **Шлюз** | часть web и worker | Единственная дорога в интернет: каждое внешнее соединение (Telegram, push-сервисы, облачные модели, загрузка моделей анализа) идёт через него — с прокси и DNS, если они заданы на вкладке «Шлюз». Соединения внутри сервера (Navidrome, локальные модели, audio) идут напрямую. |
| **Плагины** | внутри web и worker (+ свои контейнеры) | Необязательные части: добавляют задачи, страницы, вкладки настроек, приложения на «Приложения», команды бота. Выключаются на вкладке «Плагины». |

## Как ходят данные {#flows}

### Прослушивание

1. Плеер на телефоне обращается к адресу Kurai, обратный прокси отправляет `/rest/` прямо в Navidrome — web в воспроизведении не участвует.
2. Navidrome отдаёт музыку и записывает, что слушали, звёзды и оценки.
3. worker раз в полчаса забирает прослушивания из Navidrome в PostgreSQL.

В веб-плеере Kurai иначе: браузер берёт музыку у web, а web — у Navidrome от имени пользователя. О каждом треке плеер сообщает web, дослушан он или пропущен: дослушанный засчитывается в Navidrome, а «Моя волна» получает событие сразу (без ожидания «сейчас играет»), пересобирается и плеер берёт её новую версию.

### Ночная работа

В ночное окно (вкладка «Общие») worker по порядку:

1. сверяет библиотеку с Navidrome (новые и удалённые треки);
2. считает векторы новых треков моделью эмбеддингов и, если включено, разбирает звук в audio;
3. для каждого пользователя пересчитывает вкус по прослушиваниям, собирает ночные миксы (поиск похожих векторов в PostgreSQL), просит модель придумать названия;
4. записывает миксы в Navidrome как личные плейлисты — так они появляются в любом плеере;
5. выполняет ночные шаги плагинов, чистит старые миксы и задачи.

Ошибка в одном шаге не останавливает остальные: задача называет то, что не получилось.

### «Спросить»

1. Просьба приходит со страницы «Спросить» (web) или в Telegram (бот в worker) и ложится в очередь срочной задачей.
2. worker просит модель для текста превратить её в план: настроение, исполнители, длительность — или ответить на вопрос.
3. По плану worker ищет треки по векторам (теги, звук, описание звучания) с учётом вкуса и пишет плейлист в Navidrome.
4. Уведомление уходит в приложение, push-уведомлением (через шлюз и push-сервис браузера) и в Telegram.

### Вход и админка приложений

Kurai — единственная дверь: браузер входит в web; админка Navidrome и приложений плагинов открывается через web, который сам добавляет вход администратора (заголовок `Remote-User` для Navidrome). Navidrome доверяет этому заголовку только с постоянного адреса контейнера web (`KURAI_WEB_IP`). Порты контейнеров опубликованы только на `127.0.0.1` — снаружи к ним не попасть.

## Где искать, если что-то не так {#debug}

| Признак | Куда смотреть |
|---|---|
| Страницы не открываются | обратный прокси и `docker logs kurai-web` |
| Плеер не входит или нет музыки | Navidrome (вкладка «Приложения»), `docker logs kurai-navidrome` |
| Нет миксов, задачи висят | вкладка «Задачи», `docker logs kurai-worker` |
| «Спросить» долго или с ошибкой | вкладка «Модели» → «Проверить модель» |
| Бот молчит, push не приходят | вкладка «Шлюз» → «Проверить» у Telegram и push |
